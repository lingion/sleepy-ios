# Sleepy iOS 对齐 Android 1.0.67 的实施计划

本计划由主代理单线执行。每批只处理一个可独立验收的切片，不开子代理，不依赖重复轮询，不使用主工作区或真实用户数据做破坏性测试。不推送或发布，不擅自关闭远程 issue。

基线是已发布 Android `v1.0.67` 的 `d0567a2602d098671fbfeaa44b03c0ce1433b4d7`，iOS 隔离工作区从 `7713d54876c64d6e4cddc7e8874253999276e569` 开始。以 [52 项源码对照](../../parity/android-1.0.67-inventory.md) 为范围，以 [验证记录](../../parity/ios-android-1.0.67-verification.md) 为证据索引。未验证和机型不支持均不能记为通过。

## 完成门槛

1. 五个公开 issue 都有原场景验收记录，涉及通知和 Apple Watch 的问题须有相应设备证据。
2. 52 项清单逐条关闭差距；原生行为可以替代 Android 界面细节，但无法等价的用户结果单独解释并请用户确认。不能将未实现的差距归为平台限制。
3. 生产工程 iOS 和 watchOS 构建通过，完整 XCTest 单元及 UI 套件实际执行且通过。iPhone、iPad、配对 Apple Watch 及第三方路径用隔离数据验证，记录结果和证据位置。

## 执行纪律

每个实现切片先读固定 Android 标签上的生产路径和邻近测试，先写可重现断言，再最小修复和复测。涉及数据库或备份时，断言通过之后也要核对主键、关联、课程内容和写事务。实际不支持的 Apple 平台行为，在说明中给出验证依据与可行替代，留待用户接受，不纳入已通过。每次暂停前记录本批已通过的命令、仍缺的证据和下一个明确动作。
